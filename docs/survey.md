# 초기 조사 (2026-11-17)

관찰(정적 분석으로 확인)과 가설(실행 확인 전)을 구분해 적는다. 실행 확인은 Mesen CE(리눅스 빌드, 헤드리스 테스트 러너, `tools/emu/`)로 한다.

## 0. 실행 관찰 (오프닝 대사, 프레임 0–1500, 입력 없음)

- 대사는 화면 y=176(22행)과 y=192(24행)에 출력. 23행·25행은 비어 있고 배경도 검정 → **8×16 한글 2줄을 22–23행, 24–25행에 둘 수 있음**(오프닝 한정 관찰, 스테이지 사이 컷신은 별도 확인 필요).
- 대사 출력 중 CHR 슬롯 2·3 = 1KB 뱅크 2·3 (`mapper.chrBanks2/3`, PPU $0800–$0FFF 내용 일치로 이중 확인).
- 오프닝 대사는 전원 직후 자동 재생, START로 건너뛰면 타이틀로 감.

## 1. 입력

| 항목 | 값 |
|---|---|
| 파일 | iNES, 262,160바이트, SHA-1 `b1cad2d3e38ccd7780437d2c83effa254576861b` |
| 본체 CRC32 | `D0EB749F` |
| 매퍼 | 18 (Jaleco SS88006) |
| PRG / CHR | 128KB (8KB 뱅크 16개, $E000 고정 = 뱅크 15) / CHR-ROM 128KB (1KB 뱅크 128개) |

## 2. 대사 엔진 (뱅크 10, $8000에 매핑) — 관찰

- `$8031`: 문자열 번호 `$03D6` → 포인터 표 `$80EC`(78개, 리틀엔디언) → `$03D8/9`.
- `$8000`: 8프레임마다 1글자 출력(`$B0 & 7`).
- `$8066` 글자 처리:
  - `FE` 종료, `FD` 2번째 줄로(열 := 26), `FC` $80프레임 대기, `FB` 창 지우기 후 열 := 0.
  - 그 외 바이트는 타일 번호 그대로. 열 `$03DB` < 26이면 줄1 `$22C3`, 아니면 줄2 `$2303`(=$22C3+64). 즉 **26칸 × 2줄, 줄 사이 빈 행 1개**(네임테이블 22행·24행, 3열부터).
  - 출력은 PPU 큐 `$E6B0`에 (원본 포인터, PPU 주소) 등록. 원본 버퍼 `$03DD` = [가로 1][세로 1][타일].
- PPU 큐 처리 `$E55B`: 원본 형식 [가로][세로][데이터…], 가로 bit7 = 반복 채우기. **가로×세로 블록을 지원**하므로 8×16 글자(가로1·세로2)를 그대로 넣을 수 있다.
- 창 지우기 `FB`: `$80DF` 표 → `$CD01` 데이터로 `$22C0`, `$2300` 두 행만 지움. 한글 2단 글자를 쓰면 23행·25행도 지워야 함.
- 탁점(゛゜)은 별도 타일로 한 칸을 차지(인라인).

## 3. 글꼴 경로 — 관찰

- `$2000 = $28`: 배경 패턴 테이블 $0000, 스프라이트 $1000(8×16).
- 가나 타일 $80–$F7 = PPU $0800–$0F7F = CHR-ROM 1KB 뱅크 2·3. 롬 안에 한 벌만 존재. $F8–$FF는 빈 칸.
- 영문·숫자·기호 $00–$3F(CHR 뱅크 0) 유지.
- 가설: 컷신 동안 CHR 슬롯 2·3에 뱅크 2·3이 매핑됨 → 실행 확인 필요.

## 4. 텍스트 지도

| 영역 | 위치 | 분량 | 상태 |
|---|---|---|---|
| 스토리·엔딩·스태프롤 | PRG $14188–$14F00 (CPU $8188–$8F00) | 78항목, 134페이지, 3,449바이트, 한 줄 최대 26바이트 | **정확** (포인터 표로 열거, 왕복 검증 통과) |
| 아이템 메뉴(무기 교환/마법 강화) | 뱅크 12: 질문 $8388(타자 출력 $82ED, PPU $2AE4), 선택 안내 블록 $83A0($81CA에서 큐 등록, PPU $2B24), 응원 $83CD(PPU $2B24). 영어 SPELL POWER UP, AXE/SPEAR/SWORD 유지 | 일본어 3개 | **정확** (뱅크 12 출력 경로 2개 열거) |
| 그 밖의 화면(타이틀·라운드 표시·게임 오버 등) | 확인한 화면은 영어(타이틀, ROUND 1-1 REMLIA) | — | 가나 표식 검사: 타이틀·오프닝·게임 오버·컨티뉴·라운드 1–17 플레이 화면에서 대사·메뉴 밖 일본어 없음(`docs/design.md`). 라운드 클리어 후 화면과 엔딩의 정상 진행은 미확인 |

## 5. 용량

- 한글 1자 = 타일 2개. 교체 가능한 칸 $80–$FF = 128타일 = **동시에 64자**.
- 한 페이지는 최대 52자(26×2)이므로, **페이지마다 필요한 글자만 담은 글꼴 뱅크 2KB**를 `FB` 시점에 CHR 슬롯 2·3으로 바꿔 끼우면 해결 가능.
- 매퍼 18은 CHR 256KB까지 지원 → CHR을 256KB로 늘리면 1KB 뱅크 128개(2KB 세트 64개) 추가 확보. 134페이지를 여러 페이지가 공유하는 세트로 묶어야 함(번역 후 산출).
- 뱅크 10 끝 $1528E–$15FFF(3,442바이트)가 $FF로 채워져 있음 → 빈 공간 후보(사용 여부 미확인).

## 6. 위험과 다음 증거

| 미해결 | 영향 | 다음 증거 |
|---|---|---|
| 23·25행이 비어 있는지 | 2단 글자 배치 가능 여부 | 오프닝은 확인 완료(§0). 스테이지 사이 컷신·엔딩 확인 남음 |
| 다른 컷신에서 CHR 슬롯 2·3 매핑 | 페이지별 글꼴 교체 방식 | 오프닝은 뱅크 2·3 확인(§0). 나머지 컷신 확인 |
| 뱅크 10 끝 $FF 영역이 정말 빈 공간인지 | 훅 코드·번역문 공간 | 참조 검색 + 실행 확인 |
| 메뉴·그림 글자 범위 | 작업량 | 뱅크 12 분석, 화면 순회 |
| CHR 확장 시 헤더·초기화·에뮬레이터 호환 | 배포 | PoC 빌드를 에뮬레이터 2종 이상에서 확인 |

## 7. 다음 단계 (PoC)

대표 페이지 1개를 한글 2줄로 출력: CHR 256KB 확장 + 페이지 글꼴 세트 1개 + 글자 출력 훅(1×2 블록) + `FB` 지우기 4행. 실행 화면으로 확인.
