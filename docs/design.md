# 구현 설계 (대사 엔진 한글화)

PoC로 오프닝 S00–S05에서 동작 확인(2026-11-17, Mesen CE 헤드리스). 근거는 `docs/survey.md`.

## 글꼴 세트

- CHR-ROM 128KB → 256KB(헤더 CHR 8KB 개수 16 → 32). 추가된 1KB 뱅크 $80–$FF = 글꼴 세트 64개.
- 세트 n: 뱅크 `$80+2n` = 타일 $80–$BF(글자 윗반), 뱅크 `$81+2n` = 타일 $C0–$FF(아랫반).
- 글자 코드 c($80–$BE, 세트당 63자) → 타일 c(위) + c+$40(아래). 코드 $BF = 공백(두 타일 모두 빈칸), 그래서 타일 $FF는 모든 세트에서 빈칸이고 원본 지우기 데이터(`$CD01` = 타일 $FF 32칸)를 그대로 쓸 수 있다.
- 글리프: Galmuri11 Condensed 12px, 잉크 2–12행·0–6열, 색 번호 3(원본 가나와 동일). `tools/glyphs.py`.
- 세트 배정: 번역문 페이지를 순서대로 훑어, 합집합이 63자를 넘지 않는 동안 같은 세트를 공유(`tools/build.py` pack_sets).

## 텍스트 형식

| 바이트 | 의미 |
|---|---|
| $80–$BE | 현재 세트의 글자 |
| $BF | 공백 |
| $FA n | 세트 n 선택(페이지 시작, 세트가 바뀔 때만) — 새 제어 코드 |
| $FB/$FC/$FD/$FE | 원본 그대로(페이지/대기/줄바꿈/끝) |

번역 안 된 항목은 원본 바이트를 그대로 두고 원래 1×1 경로로 출력한다(개발용 빌드 전용).

## 훅 (뱅크 10, $9E00–)

| 위치 | 원본 | 변경 |
|---|---|---|
| $8066 | `LDA $03DF` | `JSR pre` — $FA 처리, 해당 틱은 출력 없이 종료 |
| $8093 | `LDA #$DD / LDY #$03` | `JSR newchar / NOP` — 한글 세트면 1×2 블록 원본 [1][2][위][아래]을 $03DC–$03DF에 만들어 반환 |
| $80A9 | `LDA $03D7` | `JSR endhook` — {END} 바로 앞이 {PAGE}(창이 지워짐)일 때만 원래 글꼴 뱅크(2/3) 복원. 글자를 남긴 채 끝나는 S76·S77은 한글 세트 유지 |
| $80CD/$80D1 | 지우기 표 $80DF | 새 표: 22·23·24·25행 4줄 지우기 |

- 글꼴 슬롯 뱅크는 제로페이지 `$03`이 원천이다(뱅크 14 `$CD67`이 매 프레임 `$0154–7`로 복사하고 IRQ가 화면 분할 시점에 적용). 훅은 **`$03`만** 바꾼다. 매퍼 레지스터를 직접 쓰면 화면 그리는 도중에 바뀌어 그림 아랫부분이 1프레임 깨졌다(가나 표식 검사로 발견, 수정).
- `$03DC`는 {WAIT} 대기 타이머로만 쓰이므로 글자 출력 중에는 버퍼로 쓸 수 있다(FC가 다시 $80으로 설정).
- 화면 기록 큐는 NMI에서 처리되고 그때 $8000 뱅크는 10이 아니다(관찰: 2) → 큐 원본은 RAM에 둬야 한다.

## 검증 상태

- 오프닝 S00–S05: 한글 2줄 출력, 페이지 지우기, 번역 안 된 S06에서 원래 글꼴 복원, 타이틀 정상 — 확인.
- 개발 빌드는 번역 안 된 항목을 원래 자리에 두고 번역문만 뱅크 10 끝 빈 영역에 넣는다(패치에 원문이 섞이지 않게). 전부 번역되면 원래 영역부터 다시 채운다.
- 남은 확인: 다른 컷신에서 `$03` 원래 값(복원값 2 고정이 맞는지), 뱅크 10 끝 $FF 영역 사용 여부, 에뮬레이터 2종 이상 호환.

## 전체 대사 검수 캡처 (2026-11-17)

- `tools/emu/page_capture.lua`: 오프닝 장면에서 대사 엔진이 포인터를 읽는 순간에만 문자열 번호를 바꿔 원하는 항목을 띄우고, {WAIT}마다 화면을 저장한다. **상태 개입 증거**이며 정상 플레이 도달 증거가 아니다.
- 결과: 78항목(빈 항목 S07 제외) 136페이지 전부 캡처, 예상 페이지 수와 일치. 글꼴 세트 19개, 대사는 원래 영역 안에 모두 들어감.
- 캡처되지 않는 페이지: {WAIT} 없이 끝나는 S76 마지막("끝"), S77 마지막("정말로 끝이야~").
- 남은 확인: 실제 컷신(스테이지 사이·엔딩)에서의 정상 플레이 화면, 각 장면의 원래 글꼴 뱅크(`$03`) 값.

## 아이템 메뉴 (뱅크 12, 아이템 종류 6번 → 고정 뱅크 $CA4B → 뱅크 12 $80C2)

- 메뉴 전용 글꼴 세트 1개(현재 세트 19). 뱅크 14 `$CA66`의 `JSR $80C2`를 고정 뱅크 `menuwrap`으로 바꿔, 메뉴 진입 전에 `$03`=메뉴 세트, 복귀 후 `$03`=2로 되돌림(메뉴 진입·종료 모두 화면이 꺼진 구간).
- 타자 출력 `$8320`: 1×1 헤더 대신 `menuchar` → [1][2][위=$055F][아래=$0560]. `$0556–$0575`는 메뉴가 시작할 때 0으로 비우는 메뉴 전용 영역이라 `$0560`을 버퍼로 씀(무기 선택 상태에서만 다른 용도, 그때는 글자 출력 없음). 코드 < $80(영어)과 $FF는 아래 칸을 빈칸으로.
- 선택 안내 블록은 [w][2][윗줄][아랫줄] 형식으로 고정 뱅크에 새로 두고 `$81CA` 피연산자 교체.
- 질문·응원 문자열은 원래 자리에 덮어씀(원래 길이 이하 검사).
- 고정 뱅크 빈 영역 `$FEEE–$FFDF`(242바이트) 중 114바이트 사용.
- 검증 1(상태 개입, 컷신 도중 `$CA4B` 호출): 질문·안내·무기 선택·응원 화면 정상. 메뉴 종료 뒤 화면 깨짐은 원본도 같은 개입에서 동일 → 컷신 중 호출이라는 개입 부작용.
- 검증 2(상태 개입, 1스테이지 플레이 중 메인 루프 `$C74E`의 프레임 대기에서 `$CA4B` 호출, `tools/emu/menu_in_gameplay.lua`): 원본·한글판 모두 메뉴 종료 후 스테이지 화면 정상 복귀, 이후 이동·공격 가능. 한글판 `$03`: 메뉴 중 $A6 → 종료 후 $02(원본과 동일). 복귀 후 프레임(2600–3400) 화면이 원본과 같음.
- 남은 확인: 실제 아이템(종류 6) 획득 경로 자체는 아직 정상 플레이로 보지 못함(호출 지점만 다름).

## 검증 환경 주의

- Mesen은 게임 DB에 없는 롬(수정된 롬)에 설정 파일의 컨트롤러를 쓴다. 설정에 `Nes.Port1.Type = NesController`가 없으면 입력이 전부 0으로 들어와 "START가 안 먹는" 것처럼 보인다(`tools/emu/run_headless.sh` 기본값에 반영).

## 화면 하단 숫자 줄 수정 (D-10)

- 원인: 게임은 IRQ 분할(191번째 줄)에서 점수판 위치를 `$2006`에 `$EA:$E9`(예: `$2B00`)로 쓴다. `$2006` 첫 바이트의 `$20` 비트는 PPU 내부 주소의 세로 미세 위치(fine Y) 비트가 되므로 점수판이 2px 아래로 그려지고, 화면 마지막 2줄(238–239)에 네임테이블 30행(속성 데이터)이 타일로 보였다(값 0–5 → 숫자 타일). 원본도 같으며, 당시 TV에서는 화면 가장자리가 잘려 안 보였다.
- 수정: `$EA`를 정하는 두 곳(뱅크 14 `$C06A`, `$C216`, 원천 `$034F`)에서 `AND #$DF` 후 저장(고정 뱅크 `hudset1/2`). IRQ 쪽 쓰기 타이밍은 그대로.
- 검증: 플레이 화면 0–191줄 원본과 픽셀 동일, 점수판 2px 위로. 라운드 0–17 2,070장면에서 마지막 2줄 모두 검정, 가나 표식 0. 아이템 메뉴(분할 주소를 저장/복원) 열고 닫은 뒤에도 정상.

## 대사 속도와 A 버튼 (D-11)

- `$8022` 틱을 `tick`으로 교체: 보통 모드는 `$B0 & 3`(4프레임마다 1바이트, 원래 `& 7`).
- `$800E`(`LDA $03D7`)를 `abtn`으로 교체: 새로 눌린 A(`$F9` bit 7)가 있으면
  - 대기({WAIT}, `$03D7` bit $20) 중: `$03DC`=1 → 같은 프레임에 대기 종료.
  - 출력 중: `$03D7` bit $10(빠른 모드) 설정.
- 빠른 모드: 화면 기록 큐는 NMI당 1건만 처리(`$E1E7`에서 `$E528` 1회) → 남은 글자를 최대 15칸 블록 [w][2][윗줄][아랫줄]으로 묶어 프레임당 1건 등록. 블록 버퍼는 `$0100–$011F`(리셋 후 한 번도 쓰이지 않음: 오프닝 방치·플레이 6,000프레임씩 쓰기 추적, 최소 스택 $F3). 큐가 빈 다음에만 버퍼 재사용. {BR}은 같은 프레임에 처리, {WAIT}/{END}에서 빠른 모드 해제. 한 페이지(최대 52칸)는 4프레임 이내.
- 검증: 글자당 4프레임 측정. A 즉시 출력 → 1–2프레임 뒤 페이지 완성, 대기 중 A → 다음 대사. 78항목 136페이지를 보통 출력/페이지마다 A 즉시 출력으로 각각 캡처해 비교: 글자 영역 픽셀 동일(차이 4건은 컷신 그림 애니메이션 프레임 차이). 가나 표식 0. START 건너뛰기, 정상 흐름 시작 컷신, 아이템 메뉴 회귀 없음.

## 화자 분리와 화자 표시 (D-12, D-13)

- `{SPLIT}`: 번역 파일에서 원문 {BR} 자리에만 쓰는 화자 전환 표시. 빌드 시 {WAIT}{PAGE}. 원문 구조 검사는 {SPLIT}을 {BR}로 보고 비교.
- 화자 표: `data/script_ko.json`의 `speakers`(글자가 있는 페이지마다 이름 또는 null), 불확실한 판단은 `speaker_notes.uncertain`.
- 새 제어 코드 `$F9 n c1..cn`(페이지 시작, `$FA` 뒤): 이름을 `[이름]` 1×2칸 블록 하나로 `$0100` 버퍼를 거쳐 PPU `$22C3`에 출력. 큐가 비어야 진행.
- 배치: 이름 22–23행, 대사 줄 24–25행·26–27행(줄 기준 표 `$80E8`을 `$2303/$2343`으로, 빠른 모드 주소 계산도 같이). 지우기 표 6행(22–27).
- 처음엔 이름을 20–21행에 두었으나 20행이 컷신 그림 쪽 화면 분할 구역(그림용 CHR 뱅크)에 걸려 장면에 따라 이름 윗줄이 깨짐 → 대사를 한 줄씩 내림. 26–27행은 모든 캡처 장면에서 비어 있음 확인.
- 대사가 원래 영역을 넘어 뱅크 10 끝 빈 영역을 일부 사용(코드 참조 없음 확인).
- 검증: 78항목 139페이지 보통/A 즉시 출력 캡처 — 페이지 수 일치, 22–27행 픽셀 동일, 글자 색 1개(깨진 색 없음), 가나 표식 0. 정상 흐름 시작 컷신 S08–S12 진행 정상.
